# Pitfall: Editing Generated Binding Files

## What Goes Wrong

You see a binding like `m.def("relu", ...)` in `python_torch_functions_2.cpp` and edit it to add a new overload. The change appears to work. Then on the next build, `python/setup.py build` regenerates the file from `native_functions.yaml` and your change is silently deleted.

## Why

`python_torch_functions_*.cpp` is generated by `torchgen` from `native_functions.yaml`. The file header contains `@generated` and a comment instructing readers not to edit it.

The pre-edit-block-generated.sh hook blocks edits to files matching the generated pattern:
- `torch/csrc/autograd/generated/`
- `python_torch_functions_*.cpp`
- Any file with `# @generated` header

These files are valid to **parse** for boundary table construction (they show which Python names map to which C++ functions). They are NOT valid citation sources.

## Fix

To add a new op:
1. Edit `aten/src/ATen/native/native_functions.yaml` — add the `func:` entry
2. Edit the C++ implementation in `aten/src/ATen/native/`
3. Run codegen: `python setup.py develop`
4. The generated files update automatically

`aten/src/ATen/native/native_functions.yaml:9 — "- func: _cast_Byte(Tensor self, bool non_blocking=False)"`
